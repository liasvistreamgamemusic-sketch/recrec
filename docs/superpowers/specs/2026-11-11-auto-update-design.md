# recrec 設計書 — 起動時のアップデート確認とワンクリック更新

- 作成日: 2026-11-11
- 対象: Windows 10/11 (x64) のインストーラー版でワンクリック更新。ポータブル版と他 OS は通知のみ
- 前提: リリースは GitHub Releases (公開リポジトリ) に `recrec-<ver>-setup.exe` /
  `recrec-<ver>-windows-x64.zip` / `SHA256SUMS.txt` の 3 点で出ている (`.github/workflows/release.yml`)

## 1. 目的

新しいバージョンを出しても、ユーザーが GitHub を見に行かない限り気づけない。
起動時にアプリが自分で最新版の有無を確認し、あれば知らせて、ボタン 1 つで更新できるようにする。

### 1.1 やらないこと

- 確認なしの自動適用 (録音アプリのバージョンが勝手に変わるのを避ける)
- 録音中の更新。録音中はバナーも出さない
- ポータブル版の自己書き換え (実行中の exe の置き換えは別の仕組みが要る。リリースページを開くだけにする)
- 差分更新・ロールバック・プレリリースの配信チャンネル
- コード署名 (別課題。§6 の制約を参照)

## 2. ユーザーから見た動作

1. 起動すると、裏で最新リリースを確認する。起動も録音も待たせない
2. 新版があり、録音中でなければ、画面上部にバナーを出す (モーダルにしない)

   `recrec 0.2.0 が利用できます (現在 0.1.0)   [更新] [変更内容] [このバージョンをスキップ] [×]`

3. ボタンの動作

   | ボタン | 動作 |
   |---|---|
   | 更新 (インストーラー版) | setup.exe をダウンロード (進捗表示) → SHA256 照合 → インストーラーを起動して recrec を終了 |
   | 更新 (ポータブル版・Windows 以外) | ラベルは「ダウンロードページを開く」。リリースページをブラウザで開く |
   | 変更内容 | リリースページをブラウザで開く |
   | このバージョンをスキップ | そのバージョンは以後通知しない (さらに新しい版が出たらまた通知する) |
   | × | 今回の起動中だけ閉じる。次回起動時にまた出る |

4. ダウンロード中に録音を始めることはできる。その場合ダウンロードは続け、完了後は
   インストーラーを起動せず「録音を止めると更新できます」と表示し、停止後に「更新」を押せるようにする
5. 確認に失敗したとき (オフライン、GitHub 障害、レート制限) は何も表示しない。ログに警告を 1 行残す。
   スタジオではオフラインが普通なので、毎回エラーを見せない
6. ダウンロードや照合に失敗したときは、ユーザーが押した操作の結果なので、既存のメッセージ欄
   (`RecrecApp::push`) にエラーを出し、バナーは残して再試行できるようにする
7. 設定パネルに「起動時にアップデートを確認する」のチェックを置く (既定でオン)

## 3. 構成

```text
起動 ─ RecrecApp::launch ─┬─ (設定がオンなら) 確認スレッドを起動
                          │        │ GET api.github.com/repos/<owner>/<repo>/releases/latest
                          │        ▼
                          │   UpdateEvent::Available(Release) / UpToDate / CheckFailed
                          ▼        │ crossbeam-channel
                   RecrecApp::poll ◀┘  → バナー状態を更新
                          │ [更新]
                          ▼
                   ダウンロードスレッド ── Progress / Ready(path) / Failed ──▶ poll
                          │ Ready かつ録音中でない
                          ▼
                   platform::launch_installer → アプリ終了
```

### 3.1 モジュール

| 場所 | 責務 |
|---|---|
| `src/update.rs` (新規) | リリース情報の取得と解釈、バージョン比較、アセット選択、ダウンロード、SHA256 照合。UI に依存しない |
| `src/platform.rs` | `open_url` (ブラウザで開く)、`launch_installer` (Windows のみ)、インストーラー版かどうかの判定 |
| `src/config.rs` | `skip_update_check: bool`、`skipped_version: Option<String>` を `AppConfig` に追加 |
| `src/ui/app.rs` | スレッドの起動、`poll` でのイベント受信、更新状態 (`UpdateState`) の保持 |
| `src/ui/view.rs` / `widgets.rs` | バナーと設定のチェックボックス |

`update.rs` の中で、ネットワークに触らない部分 (JSON → `Release`、バージョン比較、
`SHA256SUMS.txt` の解釈、アセット選択) を純粋関数にし、単体テストの対象にする。

### 3.2 設定キー

`AppConfig` は `#[serde(default)]` + `derive(Default)` なので、既定値が `false` / `None` に
なる名前にする (既存の設定ファイルをそのまま読める)。

| キー | 型 | 既定 | 意味 |
|---|---|---|---|
| `skip_update_check` | bool | false | true なら起動時に確認しない |
| `skipped_version` | 文字列 / null | null | ユーザーがスキップしたバージョン。これと同じ版は通知しない |

### 3.3 定数 (名前付き定数として `update.rs` に置く)

- リリース API の URL: `env!("CARGO_PKG_REPOSITORY")` から組み立てる (リポジトリ名を二重に持たない)
- 接続・読み取りタイムアウト: 10 秒
- ダウンロードの上限サイズ: 200 MB (現行の setup.exe より十分大きい値。超えたら中断)
- User-Agent: `recrec/<バージョン>` (GitHub API は User-Agent 必須)

## 4. 詳細

### 4.1 新版の判定

- `releases/latest` はドラフトとプレリリースを含まないので、そのまま最新の正式版として扱う
- `tag_name` の先頭の `v` を取り、`env!("CARGO_PKG_VERSION")` と SemVer として比較する。
  **厳密に新しい**ときだけ通知する (同じ・古い・解釈できないタグは通知しない。解釈できない場合はログに残す)
- `skipped_version` と一致する版は通知しない
- 確認は起動ごとに 1 回。未認証 API の制限 (IP あたり 60 回/時) には通常届かない。届いた場合は §2-5 の扱い

### 4.2 インストーラー版の判定

Inno Setup はインストール先にアンインストーラー `unins000.exe` を置く。
実行中の exe と同じフォルダーにこれがあればインストーラー版、なければポータブル版とみなす。
判定を誤っても害が小さい向きに倒れる (インストーラー版をポータブルと誤認 → ページを開くだけ)。

### 4.3 ダウンロードと照合

1. リリースのアセットから `recrec-<ver>-setup.exe` と `SHA256SUMS.txt` を名前で選ぶ。
   どちらかが無ければ「ダウンロードページを開く」に切り替える
2. ダウンロード URL は API が返した `browser_download_url` だけを使い、`https://github.com/` で
   始まることを検証する (それ以外は拒否)
3. 保存先はアプリのローカルデータ (`logs` と同じ階層) の `updates/`。ファイル名は API の値を使わず、
   検証済みのバージョンから自分で組み立てる (パストラバーサル対策)。`.part` に書いて照合後にリネーム
4. `SHA256SUMS.txt` の該当行と、ダウンロードしたファイルの SHA256 を比較する。
   不一致ならファイルを消してエラーにし、インストーラーは起動しない
5. 起動時に `updates/` の古いファイルを消す (更新後に setup.exe を残さない)

### 4.4 インストーラーの起動

- `setup.exe /SILENT` を起動し、設定を保存して recrec を通常の終了経路 (`shutdown`) で閉じる。
  `/SILENT` は進捗だけを表示し、ウィザードの質問を出さない。前回のインストール先・権限モードは
  Inno Setup が引き継ぐ
- 更新後に recrec を自動で開き直すため、`installer/recrec.iss` の `[Run]` から `skipifsilent` を外す。
  **未確認**: `/SILENT` で `postinstall` エントリが意図どおり実行されること、および管理者インストール
  (全ユーザー向け) の場合に UAC 昇格後の起動が問題ないことは、実機で確かめる。だめなら
  更新専用の `[Run]` エントリ (`Check:` で `/SILENT` 時のみ) に切り替える
- 録音中 (`is_busy()`) は起動しない (§2-4)。インストーラーは `CloseApplications=yes` で
  recrec を閉じに来るため、ここを守らないと録音が切れる

### 4.5 依存クレートの追加

| クレート | 用途 | 備考 |
|---|---|---|
| `ureq` | HTTPS GET (ブロッキング。専用スレッドで使う) | async ランタイムを持ち込まない。TLS は rustls |
| `sha2` | SHA256 | |
| `semver` | バージョン比較 | |

いずれもバージョン・API は**未確認**。実装計画の段階で公式ドキュメントと `cargo add` の結果で確定する。
JSON は既存の `serde_json` を使う。ライセンスは GPL-3.0-or-later と両立するものだけを採用する。

## 5. エラー処理

| 事象 | 扱い |
|---|---|
| 確認の通信失敗・タイムアウト・HTTP エラー・JSON 不正 | `log::warn!`。UI には出さない |
| タグが SemVer として読めない | `log::warn!`。通知しない |
| ダウンロード失敗・サイズ超過・ディスク書き込み失敗 | メッセージ欄にエラー。`.part` を削除。バナーは残す |
| チェックサム不一致・`SHA256SUMS.txt` に該当行なし | 同上。インストーラーは絶対に起動しない |
| インストーラーの起動失敗 | メッセージ欄にエラー。アプリは終了しない |
| 更新スレッドの panic | 既存の panic フックでログに残る。チャネル切断を `poll` が検知し、更新機能だけ止める |

内部のパスや HTTP 応答本文はユーザー向けメッセージに含めず、ログにだけ書く。

## 6. セキュリティ上の制約 (正直な線引き)

- `SHA256SUMS.txt` は setup.exe と同じリリースに置かれている。照合で防げるのは
  **ダウンロードの破損・途中切れ**であり、GitHub アカウントやリリースそのものが乗っ取られた場合の
  改ざんは防げない。真正性の根拠は HTTPS + GitHub のリポジトリ権限だけである
- これを強めるには、コード署名、またはアプリに公開鍵を埋め込んだ署名検証 (minisign 等) が要る。
  今回は対象外とし、必要になったら別の設計で扱う
- 更新は必ずユーザーのクリックを起点にし、無確認では何も実行しない
- 外部に送る情報は GitHub API への GET だけ (IP アドレスと User-Agent のバージョン文字列)。
  README に「起動時に GitHub へ最新版を問い合わせる。設定でオフにできる」と明記する

## 7. テスト

- 単体テスト (`update.rs`)
  - リリース JSON の解釈 (正常、アセット欠落、未知フィールド、壊れた JSON)
  - バージョン比較 (新しい / 同じ / 古い / `v` 付き / 読めないタグ / スキップ済み)
  - `SHA256SUMS.txt` の解釈 (該当行あり・なし、大文字小文字、行末の違い)
  - URL 検証 (github.com 以外・http を拒否)
  - 照合 (一致 / 不一致でファイルが消える) — `tempfile` を使う
- `config.rs`: 新キーの無い既存ファイルが既定値で読めること、往復できること
- 通信そのものは単体テストにしない (取得部分を薄く保ち、解釈を純粋関数に寄せる)
- 実機確認 (Windows): 0.1.x のテスト用ビルドをインストール → 新しいタグのリリースを用意 →
  バナー表示、更新、再起動、スキップ、設定オフ、オフライン起動、録音中の抑止、ポータブル版の動作

## 8. リリース上の注意

- v0.1.0 にはこの機能が無いので、0.1.0 のユーザーは次の版だけ手動で入れ直す必要がある。
  `installer/release-notes.md` にその旨を書く
- リリースのアセット名 (`recrec-<ver>-setup.exe`、`SHA256SUMS.txt`) はアプリとの契約になる。
  `release.yml` 側にコメントで明記し、変えるときはアプリ側と同時に変える
