# recrec 設計書 — ミュージシャン向けマルチチャンネル録音専用アプリ

- 作成日: 2026-11-10
- 対象: Windows 10/11 (x64)。開発・テストは Linux でも動く
- 実装言語: Rust (edition 2024)
- ライセンス: GPL-3.0-or-later (理由は §11)

## 1. 背景と目的

Windows 標準の「ボイスレコーダー」(サウンドレコーダー) は、既定の入力デバイスから
ステレオ/モノラルの 1 ファイルを録るだけである。オーディオインターフェース
の各入力を **入力ごとに別のモノラル WAV** で同時に録る、ASIO で録る、
24bit で録る、といったミュージシャン向けの用途に応えられない。

DAW を立ち上げれば録れるが、「思いついたフレーズをすぐ録る」「リハを丸ごと録る」には重い。
recrec は **起動してボタンを押すだけで、全入力をチャンネル別のファイルに高音質・確実に録る**
ことだけに特化した、無料・広告なしの録音専用アプリである。

### 1.1 想定ユースケース

| # | シーン | 必要な機能 |
|---|---|---|
| U1 | オーディオインターフェースの In1 (マイク) と In2 (ギターのライン) を同時に録り、別々のモノラル WAV を DAW に並べる | ASIO、チャンネル別モノラル保存、サンプル単位の同期 |
| U2 | In3-4 のシンセをステレオ 1 ファイル、In1/In2 はモノラルで録る | トラック単位のモノラル/ステレオ指定 |
| U3 | 弾いていて「今のよかった」と思ってから録音ボタンを押す | プリロール (押す前の数秒をさかのぼって録る) |
| U4 | 2〜3 時間のリハーサルを録りっぱなしにする | 長時間録音 (4GB 超は RF64)、スリープ抑止、ディスク残量監視 |
| U5 | PC が落ちても録音を失いたくない | ヘッダ定期更新、起動時の自動修復 |
| U6 | 録ったテイクをそのまま DAW に入れる | ファイルをウィンドウから DAW へドラッグ、BWF タイムスタンプ |

### 1.2 対象外 (やらないこと)

- 編集・再生・エフェクト (DAW の仕事)。ソフトウェアモニタリング (オーディオインターフェース本体のダイレクトモニターを使う)
- 複数デバイスの同時録音 (クロックが別なので長時間でずれる。1 デバイスの全入力に限定し、
  サンプル単位の同期を保証する)
- MP3/FLAC などの圧縮形式 (DAW 取り込み用の WAV に限定)

## 2. 要件

### 2.1 機能要件

| ID | 要件 |
|---|---|
| F1 | オーディオホスト (ASIO / WASAPI) を選べる。ASIO 版ビルドでドライバがあれば ASIO を既定にする |
| F2 | 入力デバイス・サンプルレート (デバイスが対応する値)・バッファサイズを選べる |
| F3 | 全入力チャンネルのレベルメーター (dBFS、ピークホールド、クリップ表示) を常時表示する |
| F4 | トラックを定義できる: 名前、ソース (モノラル = 1ch / ステレオ = 2ch)、録音対象 (アーム) のオン/オフ。既定は「入力 1ch ごとにモノラル 1 トラック、全アーム」 |
| F5 | 保存形式: WAV 16bit (TPDF ディザ) / 24bit (既定) / 32bit float。サンプルレートはデバイスのまま |
| F6 | 録音/停止はボタンと Space キー。経過時間・書き込み量・残り録音可能時間を表示する |
| F7 | プリロール 0〜30 秒 (既定 0)。録音開始時に、押す前の N 秒もファイルに含める |
| F8 | 出力先フォルダを選べる。テイクごとにフォルダを作り、トラックごとのファイルを置く (§6) |
| F9 | テイク一覧 (新しい順)。テイク全体またはファイル単体を DAW へドラッグできる (Windows)。エクスプローラーで開ける |
| F10 | クラッシュ・停電に備え、WAV ヘッダを 1 秒ごとに更新し、5 秒ごとにディスクへ同期する。異常終了したテイクは次回起動時に自動修復する |
| F11 | 取りこぼし (リングバッファのあふれ) を数え、録音中に警告し、テイクのメタデータに記録する |
| F12 | 録音開始前と録音中にディスク残量を監視し、閾値を下回ったら安全に停止する |
| F13 | 録音中は Windows のスリープを抑止する |
| F14 | 設定 (ホスト、デバイス、レート、バッファ、デバイスごとのトラック構成、形式、出力先、プリロール) を保存・復元する |
| F15 | デバイス切断などのストリームエラーで録音を安全に停止・確定し、再接続できる |
| F16 | 動作ログをファイルに残す |
| F17 | 録音中にウィンドウを閉じたら、録音を停止・確定してから終了する |

### 2.2 非機能要件

| ID | 要件 | 実現方法 |
|---|---|---|
| N1 | 音声コールバックで音切れ・取りこぼしを起こさない | コールバックはロックフリー SPSC リングへの書き込みとアトミック更新だけ。メモリ確保・I/O・ロックをしない (§4.2) |
| N2 | 全トラックがサンプル単位で揃う | 1 デバイス 1 ストリームから読み、同じフレームを全トラックに配る |
| N3 | 24bit 入力は無劣化 | 内部は f32。24bit 整数 ↔ f32 は仮数部 24bit で正確に表せるため、24bit 保存はビット完全一致 (テストで保証) |
| N4 | 長時間録音 | 4GiB を超えたら RF64 に自動切り替え (EBU Tech 3306) |
| N5 | 異常終了しても録音が残る | ヘッダ定期更新 + 修復処理。失うのは最大で最後の約 1 秒 |
| N6 | UI が重くても録音に影響しない | UI スレッドと書き込みスレッドを分離。メーターは 30fps で描画 |
| N7 | 配布は単体 exe とインストーラー | GitHub Actions で ASIO 有効ビルド、Inno Setup で setup.exe、zip でポータブル版 |

## 3. 技術選定

| 項目 | 採用 | 理由 / 不採用案 |
|---|---|---|
| 言語 | Rust | GC が無く音声スレッドの遅延が読める。メモリ安全。単体 exe にできる |
| オーディオ I/O | `cpal` 0.18 (`asio` feature) | ASIO と WASAPI を同じ API で扱える。24bit ASIO は `I24`、ドライバによっては `I32` で届く |
| リングバッファ | `rtrb` | リアルタイム安全な SPSC。チャンク単位の書き込み/読み出しができる |
| GUI | `eframe`/`egui` 0.37 | 単体 exe、WebView 不要、メーターの高頻度描画が軽い。日本語は eframe のシステムフォントフォールバックで表示 (Tauri は WebView2 と JS 側の二重構成になるため不採用) |
| WAV 書き出し | 自作 (`wav.rs`) | `hound` は RF64・BWF (bext)・JUNK 予約・クラッシュ修復を持たない。必要な機能が小さく、自作の方が確実に制御できる |
| ドラッグ&ドロップ | `drag` 2 (Windows のみ) | OLE の `DoDragDrop` でファイルを DAW へ渡せる |
| ファイル選択 | `rfd` | ネイティブのフォルダ選択ダイアログ |
| 設定・ログ | `serde_json` / `directories` / `log` + `simplelog` | |
| ディスク残量 | `fs2::available_space` | |

## 4. アーキテクチャ

### 4.1 スレッド構成とデータフロー

```text
 ┌──────────────────────┐   f32 インターリーブ    ┌──────────────────────┐
 │ 音声コールバック       │ ── rtrb (SPSC) ──────▶ │ 書き込みスレッド       │──▶ WAV ファイル
 │ (cpal / ドライバ側)   │                        │ (recorder.rs)        │    (トラックごと)
 │ ・サンプル形式→f32    │                        │ ・プリロール保持       │
 │ ・ピーク/クリップ計測  │                        │ ・トラックへ振り分け   │
 └───────┬──────────────┘                        │ ・ヘッダ更新/同期      │
         │ アトミック                              │ ・残量監視            │
         ▼ (MeterBank, overrun 数)                └─────▲───────┬────────┘
 ┌──────────────────────┐   コマンド (crossbeam)          │       │ イベント / 状態 (アトミック)
 │ UI スレッド (egui)    │ ───────────────────────────────┘       │
 │ ・設定・トラック編集   │ ◀────────────────────────────────────────┘
 │ ・メーター描画         │ ◀── ストリームエラー (crossbeam)
 └──────────────────────┘
```

- 入力ストリームは録音していないときも常に動かす (メーターとプリロールのため)。
  録音の開始・停止はファイルの開閉だけで、ストリームを触らない → 開始が即時でグリッチが無い。
- ストリームを作り直すのは、ホスト/デバイス/レート/バッファを変えたときだけ (録音中は変更不可)。

### 4.2 音声コールバックの規則 (N1)

1. 受け取ったバッファを、デバイスのサンプル形式 (`I16`/`I24`/`I32`/`F32`/…) から f32 に変換しながら
   リングに直接書く (中間バッファを確保しない)。
2. **フレーム単位でしか書かない**。リングの空きが足りないときは、入るだけのフレームを書き、
   残りのフレームを捨てて `overrun_frames` に加算する。フレームの途中で切らないので、
   チャンネルの並びは決してずれない。
3. チャンネルごとのピーク絶対値を `AtomicU32` (f32 のビット列) に `fetch_max` で反映する。
   非負の f32 はビット列の大小と値の大小が一致するので、整数の `fetch_max` で正しく最大値がとれる。
4. |x| ≥ 0.999 (約 −0.01 dBFS) でクリップフラグを立てる (UI がクリックで解除するまで保持)。

リング容量は `サンプルレート × チャンネル数 × 4 秒`。書き込みスレッドが 4 秒止まらない限りあふれない。

### 4.3 書き込みスレッドのループ

```text
loop {
    コマンドを全部処理 (Start / Stop / SetPreRoll / Shutdown)
    リングから読めるだけ読む (フレーム単位)
      ├ 録音中   : トラックごとにサンプルを抜き出し、各 WavWriter に書く
      └ 非録音中 : プリロールのリングに積む (古いものから捨てる)
    読めるものが無ければ、コマンドチャネルを 5ms 待つ
    1 秒ごと : 全ファイルのヘッダ (サイズ欄) を更新
    5 秒ごと : 全ファイルを sync_data (OS キャッシュをディスクへ)
    2 秒ごと : ディスク残量を確認。閾値 (256MiB) 未満なら停止してエラーを通知
}
```

- 書き込みエラー (ディスクフル、USB ドライブ抜け等) が出たら録音を停止し、
  確定できるファイルは確定して `Error` イベントを UI に送る。
- 停止時はリングに残っているぶんを書き切ってからファイルを確定する。

### 4.4 UI と書き込みスレッドの契約

- コマンド (`crossbeam_channel`):
  - `Start(TakePlan)` — テイクフォルダ・トラック・形式・開始時刻
  - `Stop`
  - `SetPreRoll(秒)`
  - `Shutdown` — 録音中なら停止・確定してからスレッド終了
- イベント (`crossbeam_channel`): `Started { take_dir }` / `Stopped(TakeSummary)` / `Error(String)`
- 状態 (アトミック): `recording`、`frames_written` (UI の経過時間表示用)

## 5. WAV ファイル形式 (`wav.rs`)

### 5.1 レイアウト

すべてリトルエンディアン。チャンクの並びは固定で、サイズ欄の位置は書き込み開始時に決まる。

| オフセット | 内容 |
|---|---|
| 0 | `RIFF` (4GiB 超で `RF64` に書き換え) |
| 4 | RIFF サイズ u32 (RF64 時は `0xFFFFFFFF`) |
| 8 | `WAVE` |
| 12 | `JUNK` + サイズ 28 + 0 埋め 28 バイト — RF64 の `ds64` 用の予約領域 |
| 48 | `fmt ` (16 バイト): 形式タグ (PCM=1 / IEEE float=3)、ch 数、レート、バイトレート、ブロック長、ビット数 |
| 72 | (float のみ) `fact` (4 バイト): サンプルフレーム数 |
| ... | `bext` (602 バイト, BWF): 説明、作成者 `recrec`、作成日時、TimeReference (0 時からのサンプル数) |
| ... | `data` + サイズ u32 (RF64 時は `0xFFFFFFFF`) + サンプル |
| 末尾 | data が奇数バイトなら確定時にパディング 1 バイト |

- 24bit も `WAVE_FORMAT_EXTENSIBLE` ではなく PCM (1) にする。BWF (EBU Tech 3285) と同じ形で、
  主要 DAW (Pro Tools / Cubase / Studio One / Reaper / Ableton / Logic) が確実に読める。
- `bext` の TimeReference に録音開始時刻 (プリロールぶんを差し引いた時刻) を入れる。
  同じテイクの全ファイルは同じ値を持つので、「元の時間位置に配置」できる DAW ではそのまま揃う。

### 5.2 サンプル変換

| 出力 | 変換 |
|---|---|
| 16bit | x × 32768 に TPDF ディザ (±1LSB の三角分布) を加え、丸めて [−32768, 32767] にクリップ (24bit と同じ 2 のべき乗スケールにし、16bit 入力は元の格子に戻す) |
| 24bit | x × 8388608 を丸めて [−8388608, 8388607] にクリップ。24bit 入力は完全に元の値に戻る |
| 32bit float | f32 をそのまま (0dBFS を超えた値も保持) |

ディザの乱数はトラックごとに別の種で始める (チャンネル間でノイズが相関しないように)。
暗号用途ではないので xorshift を使う。

### 5.3 ヘッダ更新・RF64・修復

- `flush_header()`: バッファを書き出し、RIFF サイズ・data サイズ・fact を現在値で上書きしてから
  ファイル末尾へ戻る。1 秒ごとに呼ぶので、異常終了しても直前までの WAV として読める。
- RIFF サイズが u32 を超えたら RF64 にする: 先頭を `RF64`、`JUNK` を `ds64` (RIFF サイズ u64・
  data サイズ u64・サンプル数 u64・テーブル長 0) に書き換え、u32 の欄は `0xFFFFFFFF`。
  一度 RF64 になったら戻さない。
- 修復 (`repair_wav`): チャンクをたどって `data` の開始位置を見つけ、
  `ファイル長 − data 開始位置` をブロック長の倍数に切り捨てた値を data サイズとして書き直す
  (端数バイトは切り詰める)。ヘッダの書き直しは書き込み時と同じ関数を使う。

## 6. テイクの保存

```text
<出力先>/
  2026-11-10_223015/            ← テイクフォルダ (開始時刻)
    01_Vocal.wav
    02_Guitar.wav
    03_Synth.wav                ← ステレオトラック
    take.json                   ← メタデータ
    .recording                  ← 録音中だけ存在するマーカー
  2026-11-10_224102_サビ案/      ← テイク名を入力した場合
```

- テイクフォルダ名: `YYYY-MM-DD_HHMMSS` + (テイク名があれば `_テイク名`)。既に存在すれば `_2`, `_3`…
- ファイル名: `<トラック番号 2 桁>_<トラック名>.wav`。Windows で使えない文字 (`\/:*?"<>|`、制御文字) は
  `_` に置き換え、末尾のドット・空白を除き、予約名 (`CON` 等) は `_` を前置する。
  トラック名が重複したらトラック番号で区別される。
- `take.json`: アプリのバージョン、ホスト、デバイス、サンプルレート、形式、トラック (名前・ソース ch・ファイル)、
  開始時刻、フレーム数、取りこぼしフレーム数、修復済みか。
- `.recording` マーカーは録音開始時に作り、正常に確定したら消す。起動時に出力先の直下を走査し、
  マーカーが残っているテイクの WAV を全部修復してからマーカーを消し、`take.json` に `recovered: true` を書く。

## 7. 画面設計 (egui)

v0.2 で全面リデザインした。設計言語は「深い黒のキャンバス + チャコールのカード + ヘアライン罫線、
差し色はラベンダーブルー 1 色」を借り、値は `src/ui/theme.rs` のトークンに集約する。

```text
┌─ 左 288px ─────────┬─ 中央 (可変) ──────────────────────────┬─ 右 340px ───────┐
│ ● recrec     v0.x  │ ┌────────────────────────────────────┐ │ テイク 3 件     ⟳ │
│                    │ │ (●)  ● 待機中       テイク名 [     ] │ │ ┌──────────────┐ │
│ オーディオ           │ │      00:00.0                       │ │ │⠿ 2026-…   開く│ │
│  ホスト   [ASIO   ▾]│ │      8 トラック · 24-bit · 48 kHz   │ │ │ 00:05 · 8 ファイル│
│  デバイス [……     ▾]│ └────────────────────────────────────┘ │ │ [01_In1.wav] …│ │
│  [48 kHz ▾][既定  ▾]│ トラック 8/8 を録音      リセット [+ 追加] │ │ └──────────────┘ │
│  ● 接続中 · 8 入力 ⟳ │         -60  -48  -36  -24  -12  0     │ │                  │
│                    │ (●) 01 [In1 ][In 1 ▾] ▮▮▮▮▯▯ -12.3 削除 │ │                  │
│ 録音                │ (●) 02 [In2 ][In 2 ▾] ▮▮▯▯▯▯ -18.0 削除 │ │                  │
│  形式 [16|24|32f]   │                                        │ │  ┌ トースト ────┐ │
│  プリロール ─●── 0 秒 │                                        │ │  │ 保存しました  │ │
│  出力先 [C:\…  変更 開く]│                                     │ │  └─────────────┘ │
│ 空き … あと約 … 時間  │                                        │ │                  │
├────────────────────┴────────────────────────────────────────┴──────────────────┤
│ Space で録音 / 停止                                                         履歴 │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **主役は録音ボタンと経過時間**。設定は左列に寄せ、録音中は変更できない項目を薄く表示する。
- **トラック 1 行 = 1 ファイル**。メーターは行の中に 1 本 (ステレオは 2 段)。LED 風に 2 dB ごとに区切り、
  −18 dB 未満は緑、−6 dB 未満は黄、それ以上は赤。表示値は 20 dB/秒で減衰、ピークホールド 1.5 秒。
  クリップすると `CLIP` バッジが出て、クリックで消える。アームを外した行は沈んだ色になる。
- **テイクはカード**。ファイルはチップで、つかんで DAW へドロップする (Windows)。
  カード左上のハンドルは全ファイルをまとめて運ぶ。
- **通知はトースト** (右下、数秒で消える)。過去の通知は「履歴」で見られる。
- **色の使い分け**: ラベンダーはフォーカスリング・選択・スライダーのみ。赤 = 録音/クリップ/エラー、
  緑 = 接続中/メーター低域、黄 = 警告/メーター中域 (状態を表す機能色で、装飾には使わない)。
- **フォント**: 欧文 Inter、数字と時間は JetBrains Mono、アイコンは Phosphor (いずれも同梱)。
  日本語は OS のフォントにフォールバックする。
- **モーション**: 録音ボタンの丸↔四角の変形とパルスリング、状態ラベルの点滅、ホバー、アームの切り替え、
  形式セレクターのスライド、カード/行のフェードイン、トーストの出入り。
  Windows の「アニメーション効果」がオフなら全て即時に切り替える。
- Space で録音/停止 (テキスト入力中は無効)。録音中のウィンドウ閉じは、停止・確定してから閉じる。
- 最小ウィンドウサイズは 1280×680。

## 8. 設定の保存

`%APPDATA%\recrec\config\config.json` (Linux は `~/.config/recrec/config.json`)。

| キー | 型 | 既定 |
|---|---|---|
| `host` | 文字列 (`ASIO` / `WASAPI` …) | ASIO があれば ASIO、なければ既定ホスト |
| `device` | 文字列 (デバイス名) | ホストの既定入力デバイス |
| `sample_rate` | 数値 | デバイスの既定 |
| `buffer_size` | 数値 or null | null (ドライバ既定) |
| `format` | `Pcm16` / `Pcm24` / `Float32` | `Pcm24` |
| `preroll_secs` | 数値 0〜30 | 0 |
| `output_dir` | パス | ミュージックフォルダ\recrec |
| `tracks` | `{ "<ホスト>/<デバイス>": [トラック…] }` | 入力ごとのモノラルトラック |

デバイスごとにトラック構成を覚えるので、IF を差し替えても構成は混ざらない。
保存されたトラックがデバイスに無いチャンネルを指していたら、そのトラックは読み込み時に捨てる。
設定ファイルが壊れていたら既定値で起動し、壊れたファイルは `config.json.bak` に退避してログに残す。

ログ: `%LOCALAPPDATA%\recrec\data\logs\recrec.log` (起動ごとに上書き、直前の 1 世代を `.old` で残す)。

## 9. エラー処理

| 事象 | 挙動 |
|---|---|
| ストリームを開けない (他アプリが ASIO 使用中など) | 状態欄に理由を表示。録音ボタン無効。⟳ で再試行 |
| ストリームエラー (デバイス切断) | 録音中なら停止・確定。エラー表示。⟳ で再接続 |
| ディスク書き込みエラー | 録音停止・確定できるファイルは確定。エラー表示 |
| ディスク残量が閾値未満 | 開始させない / 録音中なら停止 |
| リングのあふれ | 取りこぼしフレーム数を状態欄に赤で表示、`take.json` に記録 |
| アームされたトラックが 0 | 録音ボタン無効 |
| 設定ファイル破損 | 退避して既定値で起動 |

エラーは空の catch で握りつぶさず、すべてログに出し、ユーザーに見える場所 (状態欄) にも出す。

## 11. ビルド・配布

- cargo feature `asio` (= `cpal/asio`)。ローカル開発は無しでもビルドできる。リリースは有効にする。
  ASIO SDK は `asio-sys` のビルドスクリプトが Steinberg から取得する。ビルドには LLVM (libclang) が要る。
- **ライセンス**: Steinberg は 2025-10 に ASIO SDK を GPLv3 とのデュアルライセンスにした。
  ASIO を組み込んだバイナリを配布するため、recrec 自体を GPL-3.0-or-later とする。
- CI (`.github/workflows/ci.yml`): push / PR で Linux と Windows の `fmt --check`・`clippy -D warnings`・`test`。
  Windows は ASIO 有効でビルドを確認する。
- リリース (`.github/workflows/release.yml`): `v*` タグで Windows ランナーが
  1. `cargo build --release --features asio`
  2. ポータブル版 `recrec-<ver>-windows-x64.zip` (exe + README + LICENSE)
  3. Inno Setup でインストーラー `recrec-<ver>-setup.exe` (ユーザー単位インストール、管理者権限不要、
     スタートメニュー登録、アンインストーラー付き)
  4. GitHub Release を作成して両方を添付
- コード署名はしないため、初回起動時に SmartScreen の警告が出る (README に回避手順を書く)。
- release ビルドは `windows_subsystem = "windows"` でコンソールを出さない。

## 12. テスト方針

| 対象 | テスト |
|---|---|
| `wav.rs` | ヘッダの各フィールド、16/24/float のサンプル値、24bit のビット完全一致、奇数長パディング、定期ヘッダ更新後に読めること、RF64 切り替え (閾値を小さくして検証)、修復 |
| `dither.rs` | 出力範囲、平均がずれないこと、無音入力でも ±1LSB 以内 |
| `audio/capture.rs` | I16/I24/I32/F32 の変換、空き不足時にフレーム単位で捨てて数えること、ピーク/クリップ |
| `meter.rs` | ピークの最大値取得とリセット、dB 変換、減衰とホールド |
| `track.rs` | 既定構成、範囲外チャンネルの除去 |
| `take.rs` | フォルダ名・ファイル名のサニタイズ、重複時の連番、修復走査 |
| `recorder.rs` | 合成信号をリングに流し、録音→停止で各トラックのファイル内容がソース ch と一致すること、プリロールが含まれること、ステレオトラック |
| `config.rs` | 保存→読み込みの往復、壊れたファイルの退避 |

実機 (オーディオインターフェース + ASIO) の動作確認は開発環境に機材が無いため、利用者側で行う (§13 の手順)。

## 13. 実機確認手順 (利用者向け)

1. インストール後に起動し、ホスト `ASIO`・デバイスに使用するオーディオインターフェースを選ぶ
2. In1 にマイク、In2 にギターをつなぎ、メーターがそれぞれ別のトラックで振れることを確認
3. 録音 → 10 秒 → 停止。テイクフォルダに `01_…wav` と `02_…wav` ができ、DAW に並べて頭が揃うこと
4. 録音中にタスクマネージャーで recrec を強制終了 → 再起動で「修復しました」と出て、両ファイルが再生できること
